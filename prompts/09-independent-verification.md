# Prompt: Independent Verification and Acceptance Evidence

Execute `@independent-verifier`, Change: `<change-id>`.

You are the independent verifier, not the Builder. Use an independent context to verify the approved OpenSpec specs, the US/AC in the proposal-level `design/user-stories.md`, `docs/product/acceptance-policy.md`, the project baseline, design contracts, and real code. Source code, test code, specs, design, and baseline are all read-only; you may write only the verification report and evidence JSON. Do not fix issues or modify tests on the Builder's behalf.

You must record the Git commit/revision under test; if there is no commit, record the working-tree diff fingerprint and confirm during verification that it has not changed. Verify AC item by item and re-execute all applicable tests/builds/contract checks, recording commands, exit codes, and evidence. The Builder's report is a lead only and cannot replace independent execution.

Context: first run `python scripts/agent-context.py --stage 09 --change <change-id>` to get the condensed input; the full `inputs` are for audit only, and by default read from the condensed/on-demand list. At stage end, run `python scripts/check-output-context.py --stage 09` to check the advisory summary-output budget; over-budget is a warning, not a gate.

Methods and tools (mandatory):
- Use Superpowers `verification-before-completion`: PASS must be supported by real commands, exit codes, and test results; do not use the Builder's report or "already looked at it" to replace independent execution. Stage evidence must write `methods`, with a real evidence path, and run `python scripts/check-method-evidence.py --step 09-independent-verification --evidence <evidence.json>`.
- When a failure needs to be reproduced or a cause located, use `systematic-debugging`, read-only investigation; do not fix code or modify tests.
- Do not use `requesting-code-review`/`receiving-code-review` to replace independent verification; the Verifier is the reviewer, not the Builder under review.
- When `design/interface-catalog.csv` exists, check the interface_id contract, tests, and traceability row by row; missing tests, unexecuted tests, or unapproved differences are judged FAIL/BLOCKED; native/device/third-party boundaries without real-device/simulator/double/manual evidence must not PASS.
- When `docs/architecture/quality-gates.json` exists, independently rerun `python scripts/run-quality-gates.py <change-id> --independent --identity <verifier> --builder-identity <08 builder> --output openspec/changes/<change-id>/design/evidence/static-analysis-independent.json`, then run `python scripts/check-static-analysis.py --change <change-id> --expect-independent`; record a `static_checks` entry per blocking stack/tool (`stack_id`, `tool`, `command`, `exit_code`, `result`, `evidence`) in `independent-verification.json` and mirror it in the report's `## Static Analysis Checks`. Missing/failed/`NOT_RUN` gates, gates-file drift, or expired/invalid waivers are FAIL/BLOCKED; the verifier and builder identities must be distinct.
- You must independently run `openspec status --change <id>` and `openspec validate <id> --strict`, recording the exit codes; an OpenSpec validation failure is FAIL/BLOCKED.

Generate:
- `openspec/changes/<change-id>/design/evidence/independent-verification-report.md`
- `openspec/changes/<change-id>/design/evidence/independent-verification.json`

Fill them in per `templates/change-assets/design/independent-verification-report.md` and `templates/change-assets/design/independent-verification.schema.json` (if present). Run:
`python3 scripts/check-independent-verification.py --report <report-path> --evidence <json-path>`
and independently run `openspec status --change <id>` and `openspec validate <id> --strict`, recording commands, exit codes, and results.

Baseline interaction requirements: during verification, read the baseline snapshot and `design/baseline-binding.json` in read-only mode; if a constraint is not covered, evidence is missing, or the implementation deviates, judge BLOCKED/FAIL; do not modify code, tests, or the frozen baseline.
When UI is involved, you must also independently run `python scripts/check-figma-layout.py --change <change-id> --base-url <url> --viewport 1440x900` and `python scripts/check-design-tokens.py --change <change-id> --tokens <token.css>`, and generate the report `## UI Consistency Verification` and JSON `layout_checks` from the independent rerun results (per PAGE asserted element count, maximum deviation, tolerance, missing elements, verdict, and evidence). **Manual visual spot checks target only PAGES with differences, `UI-DERIVED`, or not included in assertions**, recording the spot-checked PAGE, reason, and conclusion; PAGES with no differences and machine PASS do not get page-by-page visual review. Reference images/implementation screenshots are no longer used as evidence; when assertions are missing, elements are missing, geometry/text/font exceeds tolerance, or tokens are inconsistent, judge BLOCKED/FAIL. Consume the exported package offline by default; spot-check real Figma by page only when the file version changes or the page is ambiguous (serially, to avoid rate limiting); do not re-read everything in full. **When a `differences` record exists but is not `deviation_approved`, PASS is not allowed.**

Only when all applicable AC have passing evidence, all required tests have actually executed with exit code 0, there are no blocking findings, and the revision is stable may you judge PASS. Any NOT_RUN / SKIPPED / PENDING cannot count as passing. On FAIL or BLOCKED, clearly state the return reason and do not enter stage 10. Do not archive OpenSpec, do not update the baseline, and do not commit or publish code.

## Mandatory Deliverable Handoff

- Input: the code diff, test report, review conclusion (including `## Static analysis`), approved specs, AC, baseline snapshot, design and test contracts, and `design/test-cases.csv` from stage 08; when `docs/architecture/quality-gates.json` exists, `design/evidence/static-analysis.json` plus the 08 builder identity; when UI is involved, `design/figma-audit.md` (target framework/transcoding notes, token actual values/PAGE specifications/state decisions), `design/figma-code/` (target framework design code), `design/figma-layout.csv` (assertion mapping), `design/evidence/figma-layout-check.json`, and the `## UI fidelity` numeric evidence in `design/evidence/code-review.md`; `docs/product/acceptance-policy.md`; `docs/product/open-questions.md` (read-only; unresolved questions must not be closed on your own during verification).
- Output: the independent verification Markdown report and JSON evidence, which must be located in the current Change's `design/evidence/`; when `docs/architecture/quality-gates.json` exists, the JSON `static_checks` must cover every blocking stack/tool (stack_id, tool, command, exit_code, result, evidence to `design/evidence/static-analysis-independent.json`), the report must contain `## Static Analysis Checks`, and the independent static evidence file `design/evidence/static-analysis-independent.json` must be written; when UI is involved, the JSON `layout_checks` must cover every PAGE (Figma node, asserted element count, maximum deviation/tolerance, missing elements, verdict, evidence), the report must contain `## UI Consistency Verification`, and it must record the manually spot-checked PAGES/reasons (only difference, `UI-DERIVED`, or unasserted PAGES).
- Downstream input: stage 10 reads only the PASS verification report, AC evidence, test exit codes, findings, `static_checks`, `layout_checks`, and revision.
- Handoff: generate `templates/workflow/step-handoff-report.md`; run `python scripts/workflow.py request-review --step 09-independent-verification --evidence workflow/evidence/09-independent-verification.json --summary "<review summary>"`, present the report, and end the turn. Do not run `transition` until the user explicitly approves the pending stage (any unambiguous approval wording counts; silence and check success do not) and you have run `approve`; `transition` then generates the SHA-256 manifest and advances the state.
- State: `workflow-state.json` is read-only for this stage; advance it only through workflow commands. Before starting, run `python scripts/workflow.py check-entry --step 09-independent-verification --change-id <change-id>` (non-zero = stop). The stage may be completed only when `check-independent-verification.py` exits with code 0 and the stage evidence's gate check records that command's real exit code 0; when `docs/architecture/quality-gates.json` exists, `static_checks` must all be PASS and `test_runs` must include the independently rerun `check-static-analysis.py --change <change-id> --expect-independent` exit code 0 and the independent `run-quality-gates.py` exit code 0; when UI is involved, `layout_checks` must all be PASS, and `test_runs` must include the independently rerun `check-figma-layout.py` exit code 0. `approve` and `transition` only after the user explicitly approves the pending stage (any unambiguous approval wording counts; silence and check success do not).
- Method evidence: the stage evidence checks must record `superpowers-verification-methods` (actual use and evidence of verification-before-completion / systematic-debugging) and `openspec-validate-independent` (commands, exit codes, and logs of status/validate). Stage evidence must also write `methods`: `verification-before-completion` with a real evidence path; run `python scripts/check-method-evidence.py --step 09-independent-verification --evidence <evidence.json>`.

- **Stage boundary (mandatory):** stage completion ≠ permission to enter the next stage. After the artifacts are written and checks pass, run `python scripts/workflow.py request-review --step 09-independent-verification --evidence workflow/evidence/09-independent-verification.json --summary "<review summary>"` (the flow is frozen as pending review), show the report per the handoff template, and then **end the turn immediately**; before the user explicitly approves the pending stage (any unambiguous approval wording counts; silence and check success do not), you are forbidden to read/execute the next stage's Prompt/Skill and forbidden to create next-stage artifacts. After approval, run `python scripts/workflow.py approve --step 09-independent-verification --approver "<user>" --approved-at <YYYY-MM-DD> --evidence <approval record>`, then run `transition`. Do not fill in approver/approved_at yourself, and do not treat artifact completion or self-check passing as approval.
- State: `workflow-state.json` is written only by workflow commands; do not edit it directly or auto-cross approval points.
