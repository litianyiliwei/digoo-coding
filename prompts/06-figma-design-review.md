# Prompt: UI Design and Review (HTML-first, Figma Optional)

```text
Execute `@figma-design-review`, Change: <change-id>.

Proposal requirements and AC: <proposal-and-user-stories-paths>
Target platforms: <read from design/user-stories.md>
Project business flows/RD matrix: <product-paths>
Frontend conventions: <frontend-conventions> (visual conventions from the Visual Conventions section)
Technology decisions: <technology-decisions> (target frontend framework/component library; the 06 transcription must follow these)
Baseline binding: openspec/changes/<change-id>/design/baseline-binding.json
Design source: Design-to-HTML. HTML provenance (select one): User-provided HTML / AI-authored from requirements / Figma-to-HTML (AI conversion). User-provided HTML files: <paths-or-links>. Figma file (only for Figma-to-HTML): <figma-file-link-or-file-key>

First read the approved proposal/specs/user-stories and the project FLOW/NODE/DO/BR, and determine the page scope per declared platform.

Stage 06 is HTML-first:
- The design deliverable is `openspec/changes/<change-id>/design/ui-html/`: a self-contained, high-fidelity HTML file per PAGE per platform (`ui-html/<platform>/PAGE-00N.html`), a review entry `ui-html/index.html`, `ui-html/README.md`, and `ui-html/tokens.css`. HTML provenance is explicit: **User-provided HTML** (stakeholders directly supply the design HTML), **AI-authored from requirements**, or **Figma-to-HTML (AI conversion)** (AI reads an approved Figma file through Figma MCP and converts it to HTML; Figma is an upstream input, not the review deliverable). The design owner reviews the HTML review entry. Never require Figma MCP when HTML is user-provided or AI-authored.
- The only UI contract is `openspec/changes/<change-id>/design/figma-audit.md`: a **single file** recording the design source, HTML provenance, platform selection, token **actual values** (color hex, font size/line height, spacing/radius/shadow), text styles, block-level specifications per PAGE, state coverage and decisions, design code, assertion scope, source read records (HTML render/measure or Figma MCP), differences and pending confirmation, and UI review APPROVED.
- The machine contract is `openspec/changes/<change-id>/design/figma-code/` (one **target-framework-aligned** design code file per PAGE: for the Vue stack, `PAGE-00N.vue` + that platform's component library (Element Plus for Web, uni-app component library for mobile); for the React stack, `PAGE-00N.tsx`/`.jsx`; containing real copy/font size/spacing/hierarchy/`data-node-id`) and `figma-layout.csv` (a condensed assertion table: `page_id,platform,viewport,route,element_id,figma_node_id,x,y,width,height,dom_selector,assert_geometry,assert_text,tolerance_px,text_content,font_size,font_weight,notes`). 06 establishes the assertion subset; `route`/`dom_selector` may be filled in by 07.
- **Per-platform coverage (mandatory)**: read `- Target platforms:` from `design/user-stories.md`; every declared platform must have at least one PAGE; PAGE IDs are unique across platforms and frozen in 06. Web uses its own viewport (e.g. 1440×900); App/H5/Android/iOS/HarmonyOS use their own (e.g. 375×812 or 412×915). A platform needing no custom UI must record why.
- **Framework-aligned transcription (mandatory)**: read the overall technology decisions and transcribe each HTML page into target-framework design code; do not deliver raw HTML as implementation code. `figma-code/README.md` records the target framework, extension, component/style/token replacements and deviations; 08 ports it directly and only adds business logic. For Figma-to-HTML provenance, load the official `figma-design-to-code` Skill before `get_design_context`, read the real Figma source and convert it to HTML first, then transcode the HTML.
- **No screenshots**: reference screenshots, implementation screenshots, and pixel screenshots are not gate evidence. Automated visual regression uses `scripts/check-figma-layout.py` to compare expected PAGE geometry against the runtime DOM, and tokens are compared exactly with `scripts/check-design-tokens.py`. PAGES with no differences rely primarily on machine evidence.
- Image/SVG assets are all placed in `openspec/changes/<change-id>/design/figma-assets/`, and a `README.md` inventory is generated (filename, source node/page, sha256, dimensions); if there are no assets, write `- Assets: none`.
- Do not maintain `design/design-tokens.json`; token actual values are written into the `## Design Tokens (Actual Values)` table of `figma-audit.md`.
- When there is no UI: in `## Design Source and Selection` of `figma-audit.md`, first write `- Design source status: N/A` and `- Reason for no UI: <reason>` (the `--no-ui` check requires these lines); then run `python scripts/check-figma-audit.py --change <change-id> --strict --no-ui --reason "<reason>"` and keep its log; write a skip evidence file with `step_id`, `change_id`, `"skip": true`, `reason`, and that check command/exit code/log; then run `python scripts/workflow.py skip-stage --step 06-figma-design-review --change-id <change-id> --evidence workflow/evidence/06-figma-design-review-skip.json`. A no-UI stage does not need a human Stage 06 review; a UI Change still follows the full UI review flow below.

Execution steps:
1. Determine the HTML provenance: use `User-provided HTML` when the user/stakeholder supplies design HTML files, `Figma-to-HTML (AI conversion)` when an approved Figma file exists and the user wants it converted, otherwise `AI-authored from requirements`. Record the source, provenance, chooser/supplier and date in the `## Design Source and Selection` section of figma-audit.md; the design source status must be APPROVED. Do not convert a Figma file when the user supplied HTML or requested AI-authored HTML.
2. **Determine the target framework**: read `docs/architecture/technology-decisions.md` and Section 1 of `frontend-conventions.md`, and write `- Target framework: <Vue 3 + TypeScript + Element Plus / React + ...>`, `- Design code extension: <.vue / .tsx / .jsx>`, and the rationale for the choice into the `## Design Code` section of figma-audit.md; if the technology decision is PENDING/conflicting/unreadable, block; do not choose on your own.
3. **Determine the platform/page scope**: read `- Target platforms:` from `design/user-stories.md`; allocate globally unique PAGE IDs to every declared platform and record the platform coverage in figma-audit.md. 07–10 must not add or rename PAGEs.
3a. **Requirements coverage matrix (mandatory)**: in `## Requirements Coverage` of `figma-audit.md`, map every AC and US from `design/user-stories.md` to at least one PAGE for every declared platform, or `N/A + reason`; every PAGE must map back to at least one requirement. `FULL` means the page/block and states demonstrate the requirement; `PARTIAL` requires an approver note and does not satisfy completion; `N/A` needs a reason. The design owner confirms completeness/consistency with `- Coverage review status: APPROVED` and `- Coverage reviewed by:`. Keep block references (`PAGE-00N-E0N`) aligned with `figma-layout.csv`.
4. **Produce the HTML design**: for `User-provided HTML`, read the supplied real files and normalize them into `design/ui-html/<platform>/` per PAGE (record supplier/date); for `AI-authored from requirements`, author one self-contained HTML per PAGE per platform; for `Figma-to-HTML`, read the real Figma file/nodes through Figma MCP and convert each PAGE to self-contained HTML. In all cases create `index.html`, `README.md`, `tokens.css`, use real copy/CSS token values, responsive rules per platform viewport, `data-node-id` on asserted blocks, and no external network dependencies. Then render/measure the real HTML files at their viewports and record token actual values, block geometry/text/font and page specifications in figma-audit.md and `figma-layout.csv` under `## HTML Read Records` (including the Figma read/conversion row for Figma-to-HTML).
5. **Transcode**: transcribe each HTML page (or the `get_design_context` reference implementation) into target-framework design code `figma-code/PAGE-001.vue … PAGE-00N.vue` (React stack `.tsx`/`.jsx`); preserve real copy/font size/spacing/radius/hierarchy and `data-node-id`, substitute the target component library and project tokens, produce only static high-fidelity pages and do not connect business APIs. Download any image/SVG assets immediately to `figma-assets/`.
6. Establish the PAGE → platform/source mapping, block-level actual specifications per PAGE, state coverage (at least default, loading, empty, error, permission denied/degraded, offline/weak network, push/deep link where applicable, and Android/iOS/HarmonyOS differences), and differences/pending confirmation in figma-audit.md; establish the assertion subset in `figma-layout.csv` with matching platform/viewport values, and explain the assertion scope in `## Assertion Scope`. When a state has no design frame, you must write the 07 design decision, approver, and rationale; you may not claim it has been reproduced.
7. The user/design owner must complete the UI review on the HTML review entry (or the real Figma review file when that source is selected), and write `- UI review status: APPROVED`, `- Reviewer: ...`, and `- Review evidence: workflow/evidence/06-figma-ui-review.md` into `## UI Review` (the file must actually exist).
8. If the selected source cannot be produced or read, block; do not substitute screenshots, fabricated text, or another source without recording the source change. PAGE IDs and the per-platform page set are frozen by 06, and 07–10 must not add or rename PAGES.
9. When done, run `python scripts/check-figma-audit.py --change <change-id> --strict --require-framework`; the exit code must be 0. Fail if the design source, platform coverage, requirements coverage matrix (every AC/US per declared platform or N/A + reason, every PAGE back-mapped, block IDs in `figma-layout.csv`, coverage review APPROVED), target framework, assertion mapping, token actual values, visible TEXT coverage, or UI review is missing.

Formal artifacts must follow the templates specified in process/TEMPLATE-POLICY.md and process/OUTPUT-TEMPLATE-MATRIX.csv; do not delete template fields. Unknown or unconfirmed items must be resolved with the design owner before the stage is submitted; the strict gates reject `PENDING`/`TODO`/`TBD`, so keep `PENDING` only in working drafts, always with a reason, owner, and blocking condition, and never in an artifact submitted for review.
Baseline interaction requirements: first read BASELINE-BRIEF.md, then read the relevant baselines according to page/frontend impact; pages, elements, and events must not bypass approved constraints. When a conflict is found, record the constraint ID and submit an exception/BCR; do not modify baseline-binding.json on your own. When done, run python scripts/baseline-governance.py check-change --change-id <change-id> --phase requirement.
```

Context: first run `python scripts/agent-context.py --stage <id> --change <change-id>` to get the condensed input; the full `inputs` are for audit only, and by default read from the condensed/on-demand list. At stage end, run `python scripts/check-output-context.py --stage <id>` to check the advisory summary-output budget; over-budget is a warning, not a gate.

## Execution Tool Protocol (Must Be Followed)

- **Loading project Skills:** load `.claude/skills/<skill-id>/SKILL.md` according to the current Agent's actual mechanism; if it cannot be loaded, report clearly and execute per this Prompt.
- **Superpowers:** when interaction/multi-platform states need clarification, use the stage-scoped mode of `brainstorming`; write conclusions into the state coverage/differences sections of `figma-audit.md`, do not write a separate design document. Stage evidence may optionally write `methods` (brainstorming with a real evidence path and landing section); if written, run `python scripts/check-method-evidence.py --step 06-figma-design-review --evidence <evidence.json>`. First confirm the actual installation and invocation method; if unavailable, use `mode=equivalent` and write `reason`.
- **OpenSpec:** run `openspec status --change <id>` and read the approved specs; this stage does not archive the Change. Commands must actually be executed and their exit codes/results reported.
- **HTML design source:** for User-provided HTML read the real supplied files; for AI-authored HTML actually create them; for Figma-to-HTML actually read the real Figma file/nodes and convert them. In all cases render/measure the HTML in a real browser capability; a render/measure step that was not executed must not be recorded as successful. No external network dependencies, no business APIs, no screenshots.
- **Figma MCP (optional):** only for Figma-to-HTML provenance or a legacy direct Figma source. Use actually available tools such as `use_figma`, `get_metadata`, `get_variable_defs`, and `get_design_context` to generate/read Figma files, nodes, components, and variables; before calling `get_design_context` for the first time you must load the official `figma-design-to-code` Skill; this stage does a **one-time complete export and transcription** (token actual values, block specifications per PAGE, target framework design code `figma-code/PAGE-00N.vue` (for the React stack, `.tsx`), `figma-layout.csv` assertion table, real image/SVG assets), and downloads assets immediately to `figma-assets/`; call serially, batched by page; do not poll node by node or run multiple Agents in parallel. The returned render is for immediate comparison only and is not saved; if the selected source is unavailable or cannot be read, block.
- **State and gates:** `workflow-state.json` is read-only for this stage; advance it only through workflow commands. Before starting, run `python scripts/workflow.py check-entry --step 06-figma-design-review --change-id <change-id>` (non-zero = stop). `approve` and `transition` only after the user explicitly approves the pending stage (any unambiguous approval wording counts; silence and check success do not). Pause on pending approvals, missing inputs, or failed verification.
- **Output report:** list the files actually read, tools actually called, files generated/modified, check results, items not executed, and next steps. Do not automatically commit, publish, archive, or overwrite existing files.

## Stage-End Audit (Must Be Executed)

- `figma-audit.md` must contain `## Design Source and Selection` with exactly one HTML provenance (User-provided HTML / AI-authored from requirements / Figma-to-HTML), `## Design Inputs and Style References`, `## Design Tokens (Actual Values)`, `## Text Styles (Actual Values)`, `## PAGEs and Nodes`, `## PAGE Key Specifications`, `## Design Code`, `## Assertion Scope`, `## State Coverage`, `## Asset List`, `## Differences and Pending Confirmation`, `## UI Review`, plus `## HTML Design Docs` and `## HTML Read Records` (HTML source) or `## MCP Read Records` (Figma source).
- Tokens must record **actual values** (color hex, font size/line height, spacing/radius/shadow); variable names alone or "N variables in total" do not count as passing; each PAGE must have a real source reference, viewport/frame size, and at least 3 block-level geometry/layout specifications.
- Every declared target platform must have at least one PAGE; every PAGE must carry a canonical platform value and a matching viewport in `figma-layout.csv`.
- `## Requirements Coverage` must exist: every AC and US has a FULL or N/A + reason row for every declared platform, every PAGE is referenced by at least one requirement, block IDs resolve to `figma-layout.csv`, and `## UI Review` records `- Coverage review status: APPROVED` with `- Coverage reviewed by:`. `PARTIAL` needs an approver note and does not satisfy completion.
- Each PAGE must have target framework design code (Vue stack `figma-code/PAGE-00N.vue`, React stack `PAGE-00N.tsx`/`.jsx`), and `## Design Code` must state the target framework, extension, and rationale for the choice; `figma-layout.csv` must cover each PAGE's key blocks and primary actions, with geometry/text/font values coming from the rendered HTML or Figma read; structural differences are written into `## Differences and Pending Confirmation`.
- Each PAGE must have a default state; for states without a design frame, you must write the 07 decision, approver, and rationale; do not claim they have been reproduced.
- Real image/SVG assets must exist in `design/figma-assets/` and be registered by `README.md`; **reference screenshots must not be registered or saved**.
- HTML source read records must include actually successful render/measure steps of the real HTML files (and a real Figma read/conversion record when provenance is Figma-to-HTML); Figma read records must include actually successful `get_metadata` and `get_variable_defs` calls; do not register only tool names or "not executed".
- UI review must be completed by the design owner on the HTML review entry (or the real Figma review file), and written as `- UI review status: APPROVED`, the reviewer, and an existing review evidence file.
- Run `python scripts/check-figma-audit.py --change <change-id> --strict --require-framework`; the exit code must be 0; write the audit conclusion into the handoff report.
