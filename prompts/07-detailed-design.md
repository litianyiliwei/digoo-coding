Open items go into `docs/product/open-questions.md` with an owner and blocking condition. If the stage records coverage, the evidence may include an optional `question_coverage` array: `answered` needs a real `landing`; `open` needs `owner`/`blocking`/`open_question`; `n/a` needs `reason`; `deferred` needs `reason`/`approver`/`target_step`; unknown item IDs are allowed. `## Design Decisions` must contain `### Scope and Non-Goals`, `### Key Decisions and Trade-offs`, `### Existing Code Change Impact`, `### Design Task Breakdown and Interface Scope`, `### Design Gaps and Entry Conclusion`; freeze shared interface contracts first, then refine frontend/backend; write the owner and deadline/blocking condition for undecided decisions. Existing code change communication (mandatory): load and follow the local `existing-code-impact-analysis` method Skill; first ask whether this Change modifies existing functional code or develops a new feature; if it modifies existing functional code, request the code location (repository/path/branch/commit), actually explore the relevant files/classes/functions/data structures/tests/migrations, write them into `### Existing Code Change Impact`, and register item by item the files/classes/functions/interfaces/tables/tests, modification strategy, compatibility, migration/rollback, risks, and verification method; if the code is inaccessible, mark BLOCKED. If it is new feature development, write `N/A + reason` and record that determination as the method's output. Third-party interface communication (mandatory): check against the third-party interface list from 03; for each third-party interface create a `THIRD_PARTY_API` row in `design/interface-catalog.csv`, recording provider, protocol, authentication, input/output, errors, timeout/retry/idempotency, SLA/quota, sandbox, data sharing/privacy, test_ids, owner; tests cover the sandbox, simulator, or manual verification in `interface_ids`/`fakes_env` of `test-cases.csv`. `## Interface Design` must contain `### Interface Inventory`, `### Interface Boundary Inventory`, `### Contracts and Error Semantics`, `### Interface Traceability`. `### Interface Inventory` generates `api/openapi.yaml`, defining stable operationIds, paths/methods, authentication, request/response schemas (type/required/range/enum/format/pagination), examples, error envelope, permissions, idempotency/concurrency conflicts, and version compatibility; list the IO types needed by each operationId (DB/file/Feign/Redis/MQ/Search); when there is no API, write `x-api-scope: none`, and interface traceability writes operationId → PAGE/EVT/AC and synchronizes traceability. `### Interface Boundary Inventory` must cover all cross-boundary interfaces of this Change: HTTP APIs, App↔Native (uni-app/Flutter/React Native/native bridging), App↔Device, Backend↔Third-party, Backend↔IoT, asynchronous events, file/object storage. Each interface records interface_id, type, source/target, protocol, operation/method, input/output contract, authentication, error semantics, timeout/retry/idempotency, versioning, test_ids, owner, and is written into `design/interface-catalog.csv`. If the overall technology decision is uni-app/Flutter/React Native/native App, there must be at least one `NATIVE_BRIDGE` row, and run `python scripts/check-interface-catalog.py --change <change-id> --strict --require-native`; otherwise run `--strict`. When there are no cross-boundary interfaces, write `N/A + reason` in `### Interface Boundary Inventory`, and mark `design/interface-catalog.csv` as `n/a` + `waiver_reason` in the evidence. The interface question list must at least ask about: platform form/cross-platform solution, native plugins and JS Bridge, device protocols, third-party platforms, offline/weak network/permission degradation, synchronous/asynchronous, file/object storage, version compatibility and test doubles/real devices.

`## Frontend Detailed Design` must contain `### Routing and Component Tree`, `### Design Tokens and Implementation Mapping`, `### PAGE→BLOCK→Figma Specifications`, `### PAGE→BLOCK→Component Mapping`, `### Component Responsibilities and States`, `### Event Handling`, `### State Coverage`, `### Test Mapping`, `### Responsive and Viewport Rules`, `### Page Geometry and Fidelity Assertions`. When UI is involved, you must read the target framework/transcoding notes and token **actual values** and per-PAGE block specifications in `figma-audit.md`, as well as `design/figma-code/` and `design/figma-layout.csv`; `### Design Tokens and Implementation Mapping` writes row by row Figma value → CSS variable/target component library theme/font (for the Vue stack, Element Plus + Noto Sans SC and other font stacks), and declares the global token file path (for comparison by `check-design-tokens.py`); `### PAGE→BLOCK→Component Mapping` must use the target framework design code in `figma-code/` as the baseline, state PAGE/BLOCK → design code file → implementation component path, and register only the necessary business adaptations (routing, API, events, state, permissions); do not redesign styles/layout/copy; when a visual deviation is truly needed, register a `UI-DEVIATION` (reason, impact, approver) and synchronously update `figma-layout.csv` and `## Differences and Pending Confirmation`. `### PAGE→BLOCK→Figma Specifications` writes real dimensions/spacing/padding/gap/radius/fonts and states per PAGE; do not write only "top bar, side bar, list". The PAGE list and PAGE IDs follow figma-audit.md and are frozen by 06; do not add or rename PAGES; modal/drawer/state cases not defined in Figma must be added as new Figma artboards, or recorded as `UI-DERIVED` with specific visual specifications, approver, and rationale; do not silently fabricate. **You must fill in the `route` and `dom_selector` of every row in `figma-layout.csv`**, and specify the 1440×900 baseline and the rules for ≥1440 / <1440 in `### Responsive and Viewport Rules`. Consume the exported package offline by default, and re-read Figma only when the file version changes or the page is ambiguous (serially, batched by page, to avoid rate limiting). Write the component tree, responsibilities/Props/Emits, cross-page parameters, state transitions, API calls, loading/error/empty/success/disabled/no-permission states, form validation/duplicate-submission prevention, and test IDs; distinguish server/local UI/URL state, cover the PAGE structure and key blocks/accessibility in figma-audit.md; for each interaction event write the handler's input/return/side effects/failure paths, associate the operationId, and reference the corresponding `ui-actions.csv` row by `element_id`; do not duplicate the route/params/operationId mapping in prose—`design/ui-actions.csv` is the single machine-readable action inventory. Do not rely on screenshots or fabrication. **UI action mapping (mandatory)**: enumerate every functional button/icon/link/menu/tab from `figma-code/` and `figma-audit.md` in `design/ui-actions.csv`; each row maps the control to `navigate` (`route` address + `route_params` input parameters), `api` (`operation_id` that exists in `api/openapi.yaml`), or `local-only` with the user's explicit confirmation (confirmer + date). Any control with neither navigation nor an API call must be presented to the user for confirmation; do not decide it silently. Run `python scripts/check-ui-actions.py --change <change-id> --strict`; it fails on unmapped controls or unconfirmed local-only actions. Do not rely on screenshots or fabrication. **Do not use reference screenshots or implementation screenshots.**

`## Backend Detailed Design` must contain `### API Execution Chain`, `### API→IO Mapping`, `### IO Contracts`, `### Data Model and Migration`, `### Non-Database IO`, `### Domain Types and Methods`, `### Errors and Consistency`, `### Shared Concerns`, `### Test Coverage`, `### Open Decisions`. `## Test Design` must contain `### Test Strategy`, `### Test Environment and Doubles`, `### Manual Verification`, and `### Static Analysis`. Ensure all design items are associated with REQ/AC/PAGE/EVT or have an N/A reason stated, and frontend/backend fields are consistent with OpenAPI. When done, run `bash scripts/check-change.sh <change-id>`, `bash scripts/check-design-assets.sh <change-id> --strict --lint-api`, `python scripts/check-design-sections.py --change <change-id>`, `python scripts/check-change-footprint.py <change-id> --declaration-only`, `python scripts/check-traceability.py --file openspec/changes/<change-id>/traceability.csv --strict`, `python scripts/check-test-cases.py --change <change-id> --strict`; when there is an API also run `python scripts/check-api-traceability.py --change <change-id>`; when there are cross-boundary interfaces run `python scripts/check-interface-catalog.py --change <change-id> --strict`; when UI is involved run `python scripts/check-ui-actions.py --change <change-id> --strict`; and explicitly run `openspec validate <change-id> --strict`; the exit code must be 0.
Formal artifacts must follow the templates specified in `process/TEMPLATE-POLICY.md` and `process/OUTPUT-TEMPLATE-MATRIX.csv`; do not delete template fields, write PENDING for unknown items and explain why.
