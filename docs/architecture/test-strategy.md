## 1. 测试层级与门禁

| 层级 | 目标 | 工具/命令 | 环境/依赖 | 质量门禁 |
|---|---|---|---|---|
| Unit | 领域规则、校验、状态机、金额/库存计算 | JUnit 5 + Mockito；`./mvnw test` | 无外部依赖 | 领域核心规则分支覆盖；失败阻断合并 |
| API contract | 请求/响应、错误码、鉴权、幂等 | Spring MockMvc + OpenAPI 校验；`validate-openapi.sh` | Mock 或 Testcontainers | operationId 与 schema 一致；破坏性变更阻断 |
| Service contract | 服务间 API/事件契约、服务 JWT、事件幂等 | Spring Cloud Contract 或 Pact + WireMock；Outbox 事件测试 | 多服务 Compose 或 Mock | 跨服务契约变更阻断；事件重复消费幂等 |
| Integration | 仓储、事务、Outbox、Redis、PostgreSQL/PostGIS 约束 | Spring Boot Test + Testcontainers PostgreSQL 16 + PostGIS 3 + Redis 7 | 临时容器 | 真实 PostgreSQL/PostGIS/Redis；迁移可重复 |
| Component | 页面/组件行为、权限、状态展示 | Vitest + Vue Test Utils | jsdom | 关键组件测试；快照不作为唯一证据 |
| E2E | 用户关键路径、跨页面流程 | Playwright（Web 与 uni-app H5） | 预发/本地 Compose | 关键路径通过；失败截图与 trace 保留 |
| Manual acceptance | 业务体验、视觉、监管合规 | 验收矩阵 + 人工评审 | 预发环境 | 产品负责人签字；阻断 AC 全通过 |

## 2. 后端测试规范

- 领域层测试优先：库存扣减、任务状态机、批次-码绑定、权限数据范围、预警阈值判断。
- 使用 Testcontainers 启动 PostgreSQL 16 + PostGIS 3 + Redis 7；禁止用 H2 替代 PostgreSQL/PostGIS 行为验证。
- 每个命令接口至少覆盖：成功、校验失败、权限失败、并发冲突、重复提交（幂等）。
- 服务间契约测试覆盖：MES↔IoT 遥测/预警、MES↔GIS 地块事件/图层、各服务↔platform 鉴权/审计/通知。
- 跨服务事件测试验证 Outbox 投递、重复消费幂等、失败重试与死信记录。
- GIS 测试覆盖：几何写入、空间索引、范围查询、GeoJSON schema、坐标系与空几何。
- 数据库迁移用 Flyway；每个服务 schema 从空库执行全部迁移，验证可重复与 expand/contract 兼容。
- Outbox/调度测试使用可控时钟或手动触发；异步任务必须验证重试与失败记录。
- 设备适配层使用模拟器或 WireMock；真实设备协议在阶段 08 用适配层契约测试覆盖。
- 审计日志测试验证追加、不可删除、关键字段完整；越权与失败事件必须有审计。

## 3. 前端测试规范

- 组件测试覆盖：表单校验、错误码映射、权限守卫、loading/empty/error/no-permission 状态。
- Store 测试覆盖：登录/退出、权限刷新、数据范围切换。
- API 客户端测试使用生成类型与 Mock Server；契约变更后重新生成并回归。
- E2E 覆盖关键路径：登录、计划-任务-作业、库存出入库、批次-检测-溯源、设备控制、监管看板、GIS 地块图层。
- 移动端 H5 使用 Playwright；小程序/App 目标端按 Q-005 决策后补充自动化或人工验收。
- GIS 地图测试覆盖：图层加载、无地块空态、无权限、要素过多降级、点选地块；截图只作为辅助证据。
- 视觉一致性对照 Figma 真实节点；截图只作为辅助证据，不作为唯一依据。
- 电商服务一期不测试；远期启用前单独增加订单/支付/售后契约与安全测试。

## 5. 测试数据与环境

- 测试数据使用固定种子 + 工厂；禁止使用生产个人信息。
- 每个 Change 在 `design/test-cases.csv` 登记 TEST ID、前置条件、数据、步骤、预期、失败注入、替身/环境、人工原因、自动化与清理。
- 测试环境使用 Docker Compose 测试 profile 或 Testcontainers；每次 CI 从空库初始化 `platform/mes/iot/gis` schema。
- GIS 测试数据使用固定 GeoJSON 地块与边界用例；不得使用真实测绘敏感数据。
- 附件测试使用临时目录或 MinIO 替身；禁止写入生产附件卷。
- 设备测试使用 `iot-service` 模拟器；真实设备接入前不得用生产设备做破坏性测试。
- 电商服务一期不准备测试数据；远期启用后单独定义。

## 6. 质量门禁与证据

- PR 门禁：编译、单元测试、契约校验、服务间契约测试、前端类型检查/Lint/单测、迁移检查。
- 主分支门禁：集成测试、E2E 冒烟、依赖漏洞扫描、OpenAPI 校验、跨服务 Compose 冒烟。
- 发布门禁：预发冒烟、备份检查、回滚演练记录、AC 验收证据、服务健康检查。
- 证据必须包含真实命令、退出码、日志/报告路径；未执行或跳过必须显式记录。
- 覆盖率按风险定义：领域核心规则、库存、权限、溯源、设备控制、GIS 空间查询优先；不得用覆盖率数值替代行为断言。
- Flaky 测试必须标记、隔离并限期修复；不得通过重跑掩盖失败。
- 电商服务未启用前不得出现在发布门禁；启用后单独增加支付与合规门禁。
