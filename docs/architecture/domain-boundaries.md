**唯一所有权规则**：每个 DO 或实体只能有一个所有者领域/服务；其他领域通过应用服务、查询模型或领域事件引用，不得直接写入他方拥有的 schema 或表。

## 3. 通用不变量

1. **MES 主链路**：生产计划 → 农事任务 → 作业记录 → 农资消耗 → 生产批次 → 检测报告 → 溯源码，必须可正向与反向追溯（BR-008、BR-009）。
2. **批次是溯源核心单元**：生产批次必须可关联生产计划、地块、投入品、作业记录与检测记录，支持正向与反向追溯（BR-009）。
3. **溯源码唯一**：一个批次一个有效溯源码，全局唯一、不可重复生成（BR-001）。
4. **检测报告前置**：未上传有效检测报告的生产批次不得生成溯源码（BR-002）。
5. **库存唯一写入口**：库存余额只能由 `mes-service` 的 DOM-005 通过入库、出库、盘点命令修改；DOM-004 的农资消耗必须调用库存服务，不得直接改库存表（BR-007）。
6. **任务来源可追溯**：农事任务必须记录来源为生产计划、农事模板或临时任务；执行结果必须回写任务（BR-008）。
7. **审计不可删除**：设备控制、权限变更、越权访问等关键操作必须写入 `platform-service` 的追加型审计日志，不可物理删除（BR-003）。
8. **监管只读与辖区隔离**：政府监管人员只能读取授权辖区汇总，不得下发指令或修改业务数据（BR-005）。
9. **IoT 数据所有权**：设备、遥测、阈值、预警、控制指令由 `iot-service` 拥有；MES/GIS/电商只能通过 API 或事件消费，不得直接读 IoT schema。
10. **GIS 几何所有权**：地块业务主数据 DO-001 由 `mes-service` 拥有；地块几何 ENT-029 由 `gis-service` 拥有，以 `plot_id` 引用 DO-001，不得复制或改写业务地块主数据。
11. **电商远期边界**：`ecommerce-service` 一期不部署、不落库、不开放 API；启动前必须完成产品基线修订（Q-004 范围重评），并新增电商 DO。
12. **数据保留**：传感器历史、作业记录、扫码查询与审计数据保留 2 年；到期归档或脱敏，不得无记录删除（BR-006）。
13. **消费者最小披露**：消费者扫码只返回批次公开信息，不返回用户、农场经营、库存或未授权字段。

## 4. 事务与一致性边界

- **聚合内事务**：一个命令只修改一个服务内、一个领域内的聚合及其子记录，使用本地数据库事务保证原子性。
- **跨服务写入**：通过 HTTPS API 命令或领域事件（Outbox）；禁止跨服务直接写表或共享事务。共享 PostgreSQL 实例只是部署便利，不构成数据所有权。
- **MES 内部跨域**：`mes-service` 内的 DOM-003/004/005/007 仍按领域边界通过应用服务调用；禁止跨域直接写表。
- **库存扣减**：作业记录保存与库存扣减分属 DOM-004 与 DOM-005；采用“先校验、再扣减、记录出库单”的本地事务；失败时作业记录不得标记完成，返回 409 供前端提示补货。
- **批次与溯源码**：批次、检测报告、溯源码在同一领域事务内生成；报告缺失时拒绝生成。
- **IoT 遥测**：`iot-service` 写入遥测与预警；MES 通过事件/查询消费，不直接读 IoT schema；预警通知由 platform-service 发送。
- **GIS 几何**：MES 发布地块创建/更新事件，GIS 更新几何；GIS 不参与 MES 业务事务。
- **幂等**：出入库、任务提交、溯源码生成、设备控制指令必须支持幂等键；重复请求返回首次结果。
- **并发**：聚合根使用乐观锁 `version`；唯一约束至少覆盖用户账号、溯源码、批次-码绑定、角色能力组合、设备编号、plot_id 几何。
- **补偿**：设备控制超时或失败记录为失败状态并通知人工处理；不自动重复下发非幂等指令。
- **读模型**：监管汇总、看板与报表使用只读查询模型或定时汇总表，不直接跨服务拼写业务表。

## 5. 命名、ID 与时间约定

- 公共业务 ID 使用稳定前缀：FLOW/NODE/DO/RD/BR/ROLE/CAP 沿用产品基线；领域实体在阶段 07 分配 ENT/表名。
- 技术主键使用 UUID v7 或数据库生成的 UUID，保证全局唯一与时间有序；业务编码（批次号、溯源码、订单号）另行定义，不替代技术主键。
- 数据库命名使用 snake_case；API JSON 字段使用 lowerCamelCase；枚举值使用大写下划线常量。
- 所有业务表包含 `created_at`、`updated_at`、`created_by`、`updated_by`、`version`；审计日志额外包含 `trace_id`、`result`。
- 时间统一以 UTC 存储，前端按用户时区展示；日期字段不存本地时区偏移。
- 业务记录采用状态或作废标记，不物理删除；审计日志只追加。
- schema 按服务划分：`platform`、`mes`、`iot`、`gis`；`ecommerce` 仅在未来启用时创建。
