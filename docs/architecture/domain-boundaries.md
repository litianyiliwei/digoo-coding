## 2. 服务与领域映射

- `docs/product/`、`docs/architecture/`、`docs/adr/` 是由负责人评审的产品/架构契约源。
- `prompts/`、`.claude/skills/` 是 Agent 方法和任务入口，不拥有工作流状态。
- `scripts/` 校验契约并执行受控状态迁移；`workflow-state.json` 与 `workflow/handoffs/` 由命令管理。
- `openspec/` 保存 Change 局部行为/设计/任务，不复制项目级基线事实。
- `workflow/evidence/` 保存阶段事实证据，不替代其对应规范来源。

## 3. 通用不变量

1. 单一事实只保留一个权威来源；摘要和索引只引用源路径/ID（BR-002）。
2. 各领域通过稳定 ID、仓库路径、命令参数和 JSON 契约交换信息。
3. 拒绝或待审保持在当前节点；机器检查通过不等于人工批准（BR-005）。
4. 工作流状态和交接哈希只能通过工作流命令管理。

## 4. 事务与一致性边界

- 单次 `workflow.py` 状态变更通过文件锁、临时文件和原子替换完成；失败不应留下部分 JSON 状态。
- 一次阶段交接不是跨文件事务：阶段产物先写入，证据校验通过后才执行状态迁移；若迁移失败，保留产物但阶段仍未完成。
- 多文件产物通过证据列表和哈希审查一致性；不宣称仓库级原子提交。
- Git commit 是版本快照；是否提交由用户决定，不作为状态机隐式副作用。

## 5. 命名、ID 与时间约定

- 采用 `docs/product/id-conventions.md` 的项目/Change ID 规则；架构对象以大写类型前缀及三位序号标识，如 DOM-001、DF-001、ENT-001。
- 文档日期使用 ISO `YYYY-MM-DD`；状态时间戳存 UTC ISO-8601；本地显示按 Asia/Shanghai。
- 文件哈希使用 SHA-256；工作流证据必须记录真实的命令、退出码和仓库内日志路径。
- 逻辑过程对象没有数据库主键、软删除、租户字段或业务保留期；N/A，因为本系统无运行期数据库。
