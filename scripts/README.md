# Scripts

> Language: English | [简体中文](README-zh.md)

Most scripts resolve the project root from their own location; file arguments to `validate-openapi.sh` may be absolute or relative to the current directory/project root. After copying, place scripts under the project root `scripts/` folder. Check scripts accept both the canonical English artifact section names/status markers and their Chinese equivalents, so artifacts may follow the user's language while templates stay English-first.

The scripts are intentionally fail-closed when they cannot run a required check. Adapt for Windows PowerShell if the repository does not use Bash/WSL/macOS/Linux.

| `workflow.py status` | Display workflow status | Status JSON is readable and stage IDs are valid | Business artifacts are actually complete |
| `workflow.py check-entry --step <id>` | Stage entry guard; verifies dependencies/approvals/blocks/upstream SHA-256 handoff | Stage meets entry conditions | Current stage artifact quality is correct |
| `workflow.py check-methods --step <id> --evidence <json>` | Validates the evidence `methods` block (02–10); `transition` also calls it automatically | Method evidence is recorded and references real artifacts | Question quality and decision correctness |
| `workflow.py check-coverage --step <id> --evidence <json>` | Validates the evidence `question_coverage` block (02/03/05/07); `request-review` and `transition` also call it automatically | Required checklist items are present, landed or explicitly classified | Answer quality and decision correctness |
| `workflow.py request-review --step <id> --evidence <json> --summary <text>` | Validates the stage evidence/checks, writes `workflow/evidence/<id>-review.json` with artifact hashes, and freezes the stage as pending review; `current_step` does not advance | Review packet and pending state are recorded | Artifact quality is correct |
| `workflow.py approve --step <id> --approver <name> --approved-at <date> --evidence <file>` | Verifies every reviewed artifact hash is unchanged, appends an approval record and clears that stage's pending review | User approval is registered against the exact reviewed content | Approval identity is authenticated by the script |
| `workflow.py transition --step <id> --evidence <json>` | Validates declared outputs, gates and the recorded approval, re-verifies reviewed hashes, generates the downstream handoff and atomically advances state | Stage evidence passes and state advances successfully | Manual approval identity is authenticated by the script |
| `workflow.py reopen --step <id> --reason <text>` | Rework rollback: removes the target stage and its downstream dependency closure, supersedes approvals, invalidates outgoing handoffs and returns `current_step` to the target stage | Rollback completes with reopen history and invalidation records | Does not validate artifact quality after rework |
| `workflow.py skip-stage --step <id> --evidence <json>` | Skips a conditional stage (currently Stage 06 for no-UI Changes) after a real `check-figma-audit --no-ui` check; writes a skip handoff and advances | No-UI check passed and skip record exists | Only conditional stages; UI Changes still require full review |
| `workflow.py reset-state --reason <text>` | Administrative reset to `01-project-bootstrap`: archives the previous state, clears change/approval/baseline indexes and invalidates all handoffs | Reset record and archive exist | Only for explicit user instruction; destroys active workflow position |
| `workflow.py next-change --change-id <id>` | After the current Change acceptance, archives 05–10, switches active_change_id and starts the next Change from 05 | Previous Change has completed acceptance and has no blocks | Concurrent Change scheduling is not supported |
| `workflow.py abandon-change --change-id <id> --reason <text>` | Abandons an active Change without acceptance: supersedes its approvals, invalidates its handoffs, clears 05–10 from state and records `abandoned_changes`; project stages remain complete | Active Change matches and no pending/blocked items | Does not delete the Change directory or archive it |
| `workflow.py sync-baseline-index` | Syncs the baseline version/status index of workflow-state.json from baseline-manifest.json | Status index matches the machine-authoritative Manifest | Does not freeze or modify the baseline itself |
| `workflow.py handoff-verify --manifest <json>` | Verifies handoff package file SHA-256 | Handoff files are unchanged | File semantics are correct |
| `check-independent-verification.py` | Verifies independent verification report and structured evidence; UI Changes require per-PAGE `layout_checks` (asserted elements, max delta/tolerance, missing elements) and an independent `check-figma-layout.py` run | AC/tests/revision/read-only/findings satisfy PASS rules; UI geometry was independently re-measured | Cannot prove the Verifier Agent identity is truly independent |
| `workflow.py handoff-create --from-step <id> --to-step <id> --evidence <json>` | Recovers a lost handoff manifest from the original stage's approved evidence; `--evidence` is mandatory and `--file` is rejected | Re-validates original outputs/gates/approvals and rebuilds hashes | Cannot bypass the original stage's failing gates; 09 must retain independent verification checker evidence |

| `baseline-governance.py audit [--require-frozen]` | Validates machine Manifest, domain states, file/registry SHA-256, constraint ID/source/approval; `--require-frozen` is for functional stages | Baseline metadata and file integrity pass | Not equivalent to enterprise identity authentication; requires CI/protected branches |
| `baseline-governance.py init-binding --change-id <id>` | Generates Change constraint bindings from the frozen baseline, covering all current ACTIVE Constraint IDs | Initial binding is fully generated | Applicability, design conclusions, evidence and approval still need human/Agent input |
| `baseline-governance.py check-change --change-id <id> --phase <requirement\|design\|implementation\|acceptance>` | Checks per stage: baseline snapshot, constraint coverage, exception approvals, design and implementation evidence, rebase conclusion | No baseline governance block at the current stage | Does not prove business judgment is correct; evidence semantics still need independent review |
| `baseline-governance.py open-amendment --request-id <id> --domains <csv>` | Freezes pre-amendment state, blocks functional gates | Amendment window is open | Not responsible for automatic approval or automatic version promotion |
| `baseline-governance.py refresh-hashes` | Refreshes baseline file and constraint directory hashes in DRAFT/UNDER_AMENDMENT state | Hash registry is updated | Refused in FROZEN state |
| `baseline-governance.py refresh-binding --change-id <id>` | After completing REBASE_COMPLETED review, refreshes the Change snapshot, resets change-domain determination and revokes old binding approvals | Change enters re-review | Does not replace manual re-approval |
