# Toolkit/Project Two-Repository Separation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn this repository into a pure toolkit source repository and ship the tooling (`toolkit-sync`, manifest, lock, layout checks) that lets a separate business-project repository vendor it safely and upgrade by tagged release.

**Architecture:** Phase-by-phase migration inside this repository (P1 paths/cleanup → P2 templates → P3 composed-file templates → P4 sync tooling → P5 rehearsal/guides → P6 consistency). The project side is exercised only through temp-directory fixtures; no project repository is created in this plan.

**Tech Stack:** Python 3.11 stdlib only (`pathlib`, `argparse`, `hashlib`, `subprocess`, `json`, `unittest`), Bash, Markdown/JSON/CSV. No dependency installation.

**Spec:** `process/proposals/2026-11-18-toolkit-two-repo-separation-design.md`

## 中文摘要（供快速审阅）

实施分六个阶段，每个阶段结束时工具包检查必须全绿（`check-package.py`、`test-scripts.sh`、`ci-check.sh`）。

- **P1**：删除本仓库中的项目/第三方文件（`openspec/`、`workflow/`、`workflow-state.json`、`openspec-*` Skills、`opsx` 命令），把 `docs/` 根级流程文档迁入 `process/` 并脚本化改写约 313 处引用。
- **P2**：在 `templates/` 补齐 14 个缺失产物模板与 ADR README，矩阵全部指向模板，校验器禁止以 `docs/` 产物路径充当模板。
- **P3**：新增项目初始化模板（AGENTS 托管块中英文、OpenSpec 配置模板、gitignore 块、默认 workflow-state），并把工具包自身的 AGENTS 改写为“工具包开发约定”；阶段 01 的 Prompt/Skill/契约同步更新。
- **P4**：实现 `gen-manifest.py`、`check-layout.py`、`toolkit-sync.py`（init/verify/plan/apply/repair）、`workflow.py recover-state`、`VERSION`、清单、变更日志、vendored `toolkit-ci.yml` 模板。
- **P5**：用临时目录夹具做升级演练（安装→跨版本升级→本地冲突→修复→回滚），产出证据文档与 `process/TOOLKIT-UPGRADE.md` 接入/升级指南。
- **P6**：文档一致性收尾（README/脚本说明/结构表、修正 design/ 路径漂移），全量检查通过。

**约定**：不自动提交、不安装依赖；测试先行；每阶段检查全绿；生成文件只由脚本重生成。

## Global Constraints

- **Do not commit** any change; the user commits. Do not install dependencies. Do not modify CI beyond what the tasks specify.
- Python stdlib only; all scripts run on Windows and macOS with `python`/`python3`.
- Toolkit files keep LF endings (`.gitattributes` remains authoritative). Manifest hashes are computed over UTF-8 bytes as stored.
- `workflow-state.json` (when it exists) may be written only by `scripts/workflow.py`; never edit it by hand.
- Generated documents (`process/STAGE-IO-OVERVIEW.md`, `process/TOOLKIT-MANIFEST.json`) are regenerated by their scripts; never hand-edit.
- Toolkit paths must never appear under `docs/`, `openspec/changes/`, `openspec/specs/`, `workflow/`, `design/`, `src/`, `tests/`.
- After every task run the phase checks: `python scripts/check-package.py`, `bash scripts/test-scripts.sh`, `bash scripts/ci-check.sh` (works at every phase; project checks self-skip when no baseline manifest exists).
- From Task 8 onward, any task that adds or edits files under vendored paths (`.claude/skills/<stage>/`, `.claude/hooks/`, `.claude/settings.json`, `prompts/`, `templates/`, `scripts/`, `process/` except `proposals/` and `examples/`, or `process/TOOLKIT-CHANGELOG.md`) must run `python scripts/gen-manifest.py --write` before the phase checks; CI runs `--check` and fails on a stale manifest.
- Hook constraint: `.claude/hooks/stage-boundary-guard.py` stays registered in `.claude/settings.json`; it must read `process/WORKFLOW-STAGES.json` and `process/STEP-ARTIFACT-CONTRACTS.json` after P1.

## Review Focus

Failure modes the spec implies but no single test naturally covers, each pinned to its owning task:

1. **Path rewrite overreach** — a blanket rewrite must change only the 11 process-document names and `examples/`, never project output paths such as `docs/product`, `docs/architecture`, `design/`, `openspec/changes`. Owned by Task 2 (grep assertion).
2. **Upgrade touching project outputs** — `apply` must never write or delete anything outside the manifest's vendored paths and the composed files. Owned by Task 11 (fixture asserts `docs/product` untouched).
3. **Managed-block composer losing project content** — AGENTS project sections, `context:` in `openspec/config.yaml`, and project `.gitignore` lines must survive composition. Owned by Tasks 10 and 11.
4. **Hash drift from line endings** — manifest/lock hashes must match after install on a checkout with CRLF working tree. Owned by Task 10 (hash-stability test with CRLF input).
5. **Verify blind to hand edits** — after install, editing any vendored file must make `verify` fail. Owned by Task 10.

import re, subprocess, pathlib
names = ("PROCESS-MAP|STEP-ARTIFACT-CONTRACTS|WORKFLOW-STAGES|TEMPLATE-POLICY|"
         "OUTPUT-TEMPLATE-MATRIX|BASELINE-FEATURE-INTERACTION|P0-RUNTIME-GOVERNANCE|"

pat = re.compile(r"docs/(?=" + names + ")")
changed = 0
for f in subprocess.check_output(["git", "ls-files"], text=True).split():
    p = pathlib.Path(f)
    if "process/proposals/" in f.replace("\\", "/"):
        continue
    try:
        text = p.read_text(encoding="utf-8")
    except (UnicodeDecodeError, OSError):
        continue
    new = pat.sub("process/", text)
    if new != text:
        p.write_text(new, encoding="utf-8"); changed += 1
print("rewritten", changed)
EOF
