# Toolkit Changelog

> Language: English (main) | 简体中文

> Release notes for the workflow toolkit. Projects pin a version through `toolkit-lock.json` and upgrade deliberately with `scripts/toolkit-sync.py`.

## 2.3.0 — 2026-11-27 — Tiered gate enforcement (HARD / ADVISORY / AI-OWNED) and smoother stage cadence

- **Advisory warnings and review-packet aggregation.** Added `warn()` and `extract_warnings()` to `scripts/gate_common.py`; `workflow.py request-review` now aggregates `WARN:` / `WARN (advisory):` lines from check logs and advisory method checks into `review-packet.warnings`, and `templates/workflow/step-handoff-report.md` adds `### Advisory Warnings (Non-Blocking)`.
- **Count thresholds downgraded to ADVISORY.** `check-reference-research.py` (3 questions / 3 sources / 2 comparisons / 2 deviation rows), `check-figma-audit.py` (3 tokens / 2 colors / 3 text styles), and `check-requirements.py` (`## Acceptance Walkthrough` covering all three Slice positions) now emit non-blocking warnings while keeping substantive HARD gates (at least 1 real source URL, same-category product + user-confirmed major deviations, real token values, valid AC references).
- **Method evidence split into `hard` and `advisory`.** `method_policy` in `process/STEP-ARTIFACT-CONTRACTS.json` and `scripts/method_evidence.py` now carry per-skill `level: hard | advisory` (omitted `level` defaults to `hard` for backward compatibility). Only 05/10 `baseline-impact-classification` and 09/10 `verification-before-completion` remain blocking; other method skills warn without blocking `transition`.
- **UI & design checks drop keyword-stuffing and add `local-ui`.** Removed prose filename checks (`check-figma-layout.py`, `ui-actions.csv`) from `check-design-sections.py` and `check-figma-audit.py`; `### Event Handling` now checks substantive `element_id` references (advisory). `check-ui-actions.py` and `templates/change-assets/design/ui-actions.csv` add `action_type=local-ui` (pure presentation state with reason in `notes`, no approver required), while `local-only` retains user confirmation; routine UI states (`loading`/`empty`/`error`/`toast`/`skeleton`) may be recorded as `UI-DERIVED (routine)` without an approver.
- **Stage 08 execution & communication checklists relaxed.** In `implementation-orchestrator` Skill, `prompts/08-implementation-orchestrator.md`, and managed `AGENTS.md` blocks: `read_set` is a recommended starting point (no `CONTEXT_EXPANSION` logging), TDD and intermediate verification order are AI-owned (only `check-change-footprint.py` must run after the last edit), and `MODULE.md` updates apply to new modules or external contract changes. Stage 03/07 communication checklists allow inferring clear items with `ASSUMED: <basis>` for stage-review confirmation. `governance_profile=lite` allows single-line `N/A (lite)` sections in templates.
- **Approval cadence and one-command Stage 06 skip.** `process/WORKFLOW-STAGES.json` lowers `08-implementation-orchestrator` `risk_level` to `low` (fast-trackable under opt-in `risk-based` policy; `standard` default unchanged; Stage 09 remains independent and human-approved). `workflow.py skip-stage --step 06-figma-design-review --change-id <id> --reason "<reason>"` now auto-generates minimal N/A `design/figma-audit.md`, runs `check-figma-audit.py --strict --no-ui`, and writes skip evidence when absent.
- **Migration.** Backward compatible with `2.2.0`; no workflow-state migration is required. Projects upgrade with `scripts/toolkit-sync.py`.

## 2.2.0 — 2026-11-26 — HTML-first UI, module packages, coverage gates, lean Skills, and parallel Change lanes

- **UI design stage is HTML-first.** Stage 06 (`06-figma-design-review`, identifier retained for state compatibility) now defaults to Design-to-HTML: per-platform, self-contained, high-fidelity HTML design documents under `design/ui-html/` (one page per PAGE, review `index.html`, `README.md`, `tokens.css`), with explicit provenance — user-provided HTML, AI-authored from requirements, or Figma-to-HTML conversion. The design owner reviews the HTML review entry. Figma remains an optional supplementary source and is used only when the user explicitly selects it or an approved Figma file exists; Figma MCP is no longer a mandatory stage input.
- **Per-platform UI coverage.** Stage 05 declares `Target Platforms` (`web|h5|mini-program|app|android|ios|harmonyos|desktop|pda`) in `proposal.md` and `design/user-stories.md`; the roadmap carries the same cell; stage 06 must provide at least one PAGE per declared platform. PAGE IDs stay globally unique and frozen in 06; `figma-layout.csv` gains `platform` and `viewport` columns, and `check-figma-layout.py` measures each page at its own viewport.
- **Stage 02/04/05 platform gates.** Stage 02 adds `## 10. Target Platforms and Client Forms` (explicit YES/NO per platform, at least one YES); stage 04 adds a `Target Platforms` roadmap column; stage 05 makes the proposal/user-stories declaration mandatory and machine-checked (canonical vocabulary, no hidden platforms, exact agreement across artifacts).
- **Contract files keep historical names.** `design/figma-audit.md`, `design/figma-code/` and `design/figma-layout.csv` remain the shared contract shape for both sources. In HTML mode the `figma_node_id` column stores the HTML `data-node-id`; HTML render/measure records replace MCP read records. The checker `check-figma-audit.py --strict --require-framework` now validates source/platform coverage and HTML design self-containment.
- **Module packages and Change slices.** `docs/architecture/code-layout.json` selects `module-packages` (new-project default), `footprint`, or `none`; `docs/product/capabilities.csv` and `modules.csv` track capability progress and module ownership, the roadmap gains module-aware columns, and stage 07 declares `### Implementation Slice`. The 07→08 slice declaration and 08→09 footprint checks are `workflow.py transition` hard gates, module cards (`<module_path>/MODULE.md`) are created by implementation, and an implementation lease prevents overlapping writes.
- **Parallel Change lanes and proposal dependency gates (v2 state).** `workflow.py upgrade-state`/`start-change`/`list-changes` run 05–10 per Change lane with Change-namespaced evidence, handoffs, review packets and approvals; `start-change` fails closed unless the project stages are complete, the baseline is frozen, and every roadmap dependency is ACCEPTED. `next-change` remains a compatibility alias.
- **Reference research and UI control gates.** Stage 02 requires a same-category product and user-confirmed major deviations (`check-reference-research.py`); stage 07 requires every functional control to map to navigation, an OpenAPI operationId, or a user-confirmed local-only action (`check-ui-actions.py`); the optional `question_coverage` evidence block is shape-checked.
- **HTML-assisted review coverage gate.** Stage 06 `figma-audit.md` gains a `## Requirements Coverage` matrix and the design owner records `Coverage review status: APPROVED`. `check-figma-audit.py --strict --require-framework` now verifies that every AC and US covers every declared platform (FULL or N/A + reason), every PAGE maps back to a requirement, block references resolve to `figma-layout.csv`, and no platform/PAGE mapping is inconsistent; 07 initializes `traceability.csv` from this matrix.
- **Templates and docs.** New `templates/change-assets/design/ui-html/` (README, index, token CSS) and `templates/change-assets/design/design.md`; extracted optional Figma rules to `.claude/skills/figma-design-review/references/figma-source.md`; updated `figma-audit.md`, `figma-layout.csv`, `ui-actions.csv`, requirements/goal roadmap/user-story templates, output-template matrix, template policy, question-coverage checklist, process maps, runtime governance and managed AGENTS block.
- **Lean Skills, traceability & baseline rendering, and project layout extensions.** Streamlined stage Skills (`SKILL.md`), prompts (`prompts/00..10`), and `STEP-ARTIFACT-CONTRACTS.json` lean read sets (with `agent-context.py` stage 10 fix); added `scripts/gen-traceability.py` to generate `traceability.csv` and `scripts/baseline-governance.py render-status` to render `baseline-status.md`; stabilized `stage-io-report.py` source hashing across CRLF/LF checkouts; added `project-extensions.json` support in `check-layout.py` and `toolkit-sync.py` for declared project-owned roots/paths.
- **Migration.** No workflow-state schema migration is required; the stage id and skill name are unchanged. Existing in-flight Changes without target-platform declarations must add them before stage 05/06 gates pass; existing UI Changes must add `## Requirements Coverage` and the coverage review before `check-figma-audit.py --strict --require-framework` passes; legacy Changes can still run the checker without `--require-framework` during transition.

## 2.1.0 — 2026-11-19 — Tiered static analysis gates and risk-based approvals

- **Static analysis gates (conditional).** `docs/architecture/quality-gates.json` records the adopted stacks, per-tool `blocking`/`advisory` mode, config paths, blocking severities and waiver policy; `scripts/check-quality-gates.py` validates the selection, `scripts/run-quality-gates.py` runs the blocking tools and captures per-tool logs, and `scripts/check-static-analysis.py` verifies builder and independent-verifier evidence (`design/evidence/static-analysis.json`, `static-analysis-independent.json`, `static-analysis-logs/`) including config/gates hashes, source revision and waiver validity.
- **Dormant until adoption.** No new unconditional required file. `ci-check.sh`, `verify-before-completion.sh` and `workflow.py transition` for 08/09 run the static gates only when `quality-gates.json` exists and otherwise print `SKIP_STATIC_GATES=not-adopted`; an existing project activates them through the next Stage 03 baseline amendment, and no workflow-state migration is required (`state_schema` 1.0).
- **Language kits and constraint.** Static analysis templates for Go, Java, Python, Shell, SQL and TypeScript under `templates/static-analysis/`, plus the `quality-gates.json` baseline template, `static-waivers.example.json`, static-analysis sections in `technology-decisions.md`/`test-strategy.md`, `## Static analysis` sections in code review and acceptance evidence, and the `QUALITY-STATIC-001` constraint.
- **Risk-based approvals.** `process/WORKFLOW-STAGES.json` gains `risk_level`; under the `risk-based` approval policy, low-risk stages (01, 04, 06) may run `request-review` for the audit packet and then transition without a recorded approval (`STATUS=RISK_BASED_FAST_TRACK`), while high-risk stages keep explicit human approval.
- **Question coverage relaxed.** The 02/03/05/07 checklist moves from DRAFT item-by-item enforcement to RECOMMENDED guidance: the contract policy no longer lists per-stage `required_items`, and the `question_coverage` evidence block is optional and only shape-checked when present.
- **Independent verification.** Adds `independent-verification.schema.json` and the corresponding report template; the verifier independently re-runs adopted static gates (`run-quality-gates.py --independent`) with an identity distinct from the builder, and `check-independent-verification.py` validates the evidence.
- **Checks and cleanup.** `ci-check.sh` now bundles the package self-check, script regressions, manifest check and auto-mode layout check (the explicit `check-layout.py --mode toolkit` run stays mandatory); removed the superseded `check-inventory.py`, `check-baseline-governance.py` and `scripts/legacy/` Figma helper; the manifest is regenerated for the full vendored set.

## 2.0.0 — 2026-11-18 — Two-repository separation

- **Repository model.** The toolkit lives in its own repository; each business project lives in a separate repository and vendors this toolkit at fixed paths (`prompts/`, `templates/`, `scripts/`, `process/`, `.claude/skills/<stage>/`, `.claude/hooks/`, `.claude/settings.json`, `.github/workflows/toolkit-ci.yml`).
- **Process documentation.** All toolkit process specifications moved from `docs/` to `process/`; project repositories keep `docs/` for project outputs only.
- **Templates.** Every output template lives under `templates/`; the template matrix no longer registers production paths as templates.
- **Composed files.** `AGENTS.md`, `openspec/config.yaml`, and `.gitignore` use toolkit-managed blocks maintained by `scripts/toolkit-sync.py`; project content stays outside the markers.
- **Upgrade tooling.** `toolkit-sync.py init/verify/plan/apply/repair` installs and upgrades a project repository from a tagged release; `gen-manifest.py` maintains `process/TOOLKIT-MANIFEST.json`; `check-layout.py` enforces ownership in both modes.
- **Migration.** Projects created from this release must run `toolkit-sync.py init`; no workflow-state schema migration is required (`state_schema` 1.0).
