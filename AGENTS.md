# AGENTS.md — Toolkit Repository Conventions

> Language: English | [简体中文](AGENTS-zh.md)

> Status: APPROVED (two-repository model adopted 2026-11-18; this repository is the toolkit source repository; project workflow conventions ship as `templates/workflow/agents-managed.md` and are installed into project repositories by `scripts/toolkit-sync.py`)

## Repository Role

- This repository is the AI R&D workflow **toolkit source**. Business projects live in separate repositories that vendor a released version of this toolkit and run the staged workflow there.
- Toolkit content only: `.claude/skills/<stage>/`, `.claude/hooks/`, `.claude/settings.json`, `prompts/`, `templates/`, `scripts/`, `process/`, `README*.md`, `LICENSE`, `.gitattributes`, `VERSION`.
- Never add project outputs to this repository: `docs/product|architecture|adr|project`, `openspec/`, `design/`, `workflow/`, `workflow-state.json`, `toolkit-lock.json`, or business code. `_trash/` is gitignored local history (completed plans, removed scripts, task scratch) and is never tracked.
- Project workflow rules (stage gates, template policy, UI rules, OpenSpec conventions) are not this file's concern; their authoritative managed block is `templates/workflow/agents-managed.md` (Chinese: `agents-managed-zh.md`).

## Layout and Ownership

- `process/` holds process specifications and registries; project operational paths never appear here.
- `process/proposals/` holds only plans for work still in flight. Once a plan's work lands, move its design documents, implementation plans and rehearsal evidence to `_trash/<YYYY-MM-DD>/process/proposals/`; completed planning artifacts are local history, not tracked toolkit content. Completed task scratch under `.superpowers/sdd/` is archived the same way (`_trash/<YYYY-MM-DD>/superpowers-sdd/`).
- The vendored set installed into project repositories is declared by `process/TOOLKIT-MANIFEST.json` (generated; never hand-edit).
- Third-party files generated by OpenSpec CLI (`openspec-*` Skills, `opsx` commands) belong to project repositories and are not part of this toolkit.

## Checks

Run all of the following before any review; results are fail-closed and must not be forged:

```bash
bash scripts/ci-check.sh
python scripts/check-layout.py --mode toolkit
```

`ci-check.sh` already includes the package self-check, the script regression suites, the manifest check and an `auto`-mode layout check; the explicit `--mode toolkit` run is stricter and must not be dropped.

## Generated Files

- `process/STAGE-IO-OVERVIEW.md` and `process/TOOLKIT-MANIFEST.json` are generated. Regenerate them with their scripts (`stage-io-report.py --out ...`, `gen-manifest.py --write`); never hand-edit.
- `VERSION` is bumped and the `toolkit-vX.Y.Z` tag is cut only at release time, together with a `process/TOOLKIT-CHANGELOG.md` entry.

## Release Process

1. Checks green (section above); 2. generated files regenerated; 3. `VERSION` and the changelog updated; 4. the user commits and tags. Agents never commit, tag, or release.
Projects upgrade to a tag with `scripts/toolkit-sync.py` inside their own repository.

## Project Repository Rules

- The staged workflow applies inside a business project repository. Adoption and upgrade steps are documented in `process/TOOLKIT-UPGRADE.md`.
- A project's `AGENTS.md` contains the toolkit-managed block between `<!-- toolkit:begin -->` and `<!-- toolkit:end -->`, plus project-owned content (status header, Project Goal, project conventions). Agents writing in a project must never edit inside the managed block.

## Agent Behavior Boundaries

- Do not automatically install dependencies, commit code, modify CI beyond an approved toolkit change, archive, or release.
- Do not approve undecided rules on behalf of business/design/architecture owners.
- Do not edit generated files; never copy project outputs into this repository.
- External tools (HTML design authoring/rendering, optional Figma MCP, OpenSpec CLI, Superpowers) are subject to their actual accessible capability; unreadable links/fields are not reviewed.
