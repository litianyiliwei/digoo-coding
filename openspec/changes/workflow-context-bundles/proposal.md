# Proposal

- Change ID：workflow-context-bundles
- 状态：DRAFT（阶段 05 提案）
- 来源基线：产品 v0.2.0；架构 v0.2.2（FROZEN）
- 关联需求/AC：RA-001、NFR-001、FLOW-001、NODE-001-01–04、DO-001–003、RD-001/002/003/004、BR-001–004、DEC-002/004
- 生成日期/版本：2026-11-17 / v0.1.0

## Why

当前 `agent-context.py` 主要列出文件和按需读取清单，没有渲染 Agent 实际会收到的内容，也没有计算展开后的字符数。阶段 04 上下文已占满 8/8 组，但尚不能证明是否符合已确认的 12,000 字符目标；AI 可能加载过多资料，也可能漏掉触发条件命中的约束。

## What Changes

- 提供可直接传给 Agent 的上下文包输出，按阶段配置、Change 影响标签及指定的稳定 ID/章节选择必读和条件资料。
- 为每个来源记录文件路径、选择依据、命中标签、选中章节/ID、内容哈希和字符贡献；相同输入应得到相同结果。
- 以实际渲染的上下文文本计量字符数和读取组数。默认超过 8 组或 12,000 字符时失败关闭，报告超限量和最大来源贡献；只有与当前 Change 匹配且额度覆盖本次上下文的已批准例外记录才能允许超限。
- 支持按 TASK ID 生成精简执行卡，拼接任务、关联 AC、设计中已确定的代码范围及检查命令；缺少必需字段时明确报告 PENDING/缺失，不推测或伪造。
- 保留当前清单模式和 `--full` 审计模式；不把渲染结果写成新的常驻权威文件，避免增加重复产物。

## Capabilities

### New Capabilities

- `agent-context-bundles`：依据阶段配置、影响标签和稳定 ID/章节选择实际输入文本，提供字符预算、来源证明和可选任务执行卡。

### Modified Capabilities

无。仓库当前没有已登记的 OpenSpec 主规范；本 Change 建立新的可观察工具能力。

## Impact

- 受影响工具：`scripts/agent-context.py` 及上下文选择/预算检查配置。
- 权威来源：沿用阶段契约 JSON 中的阶段输入配置；新增条件触发映射必须维护在同一权威配置内，不复制到另一份清单。
- 受影响使用者：构建 Agent 与流程负责人；输出只写标准输出/诊断流，不写入正式 Change 或基线文件。
- 非目标：不定义低/标准/高风险检查集合（Q-003）；不改变阶段审批、基线冻结、状态迁移、独立验证或任何安全硬门禁；不涉及 UI、HTTP API、数据库或外部运行服务。
- 基线归属：落实既有 BR-001/003 与 NFR-001；初步判定 `CHANGE_ONLY`。若实现发现必须改变共享预算、阶段边界或必需输入语义，暂停并重新评估基线修订。
